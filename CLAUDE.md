# CLAUDE.md — Krill

Project-level guidance for the next AI coding agent (and developers). Read this before touching code. It exists to keep you from breaking things or wasting time.

## 1. What Krill is + status

Krill is a minimal self-hosted PaaS written in Go (`github.com/proshik/krill`) — a lightweight Dokploy alternative aimed at a ~20–50 MB control plane (vs Dokploy's ~760 MB) so the author can host a webhook Telegram bot on a 2 vCPU / 1.9 GB VPS. It deploys containerized apps and managed databases on a single-node Docker Swarm, routes traffic via Traefik, and exposes a web control plane (templ + HTMX + Tailwind v4) with a multi-tenant org → project → environment → app/db hierarchy and bcrypt/cookie auth.

Status: Phases 0, 1, 2, 2.5, 3, **4, 5** are DONE (login, image apps, Swarm services, Traefik routing, live logs, rolling updates, Dockerfile build+deploy, deploy history, UI design system + i18n, managed Postgres/Redis with volumes and external ports, multi/custom domains per app + per-domain Let's Encrypt HTTPS, **Postgres backups to S3/MinIO with cron + retention + restore**). **Phase 7 (realtime/ops)** is DONE except email/Slack: Telegram notifications, web terminal, host monitoring, and the structured log viewer all shipped. Tech-debt backlog for Phases 1–3 is fully closed. The **deploy-parity** track (gaps vs Dokploy for deploying a real app) is now **fully closed**: registry credentials (private image pull), advanced container settings (resources/replicas/restart/healthcheck), app lifecycle controls (stop/start via Deploy/Reload/Rebuild/Stop), gateway route exposure (per-domain public-path allow-list, internal-by-default), container command override (CMD args via the Advanced tab, e.g. `start-dev` for Keycloak), UI delete buttons for apps/environments/projects, **app volumes/mounts + volume backup/restore, DB→app connection-string injection, raw TCP/UDP published ports, build secrets/build-args + private-git clone, and per-domain route protection (basic-auth + IP-allowlist, the "who" axis) are all DONE**. **Multi-server (cluster)** Stage 1+2 (SSH node join, placement, DB-on-node) is merged to master and live-checked on 2 nodes. **Phase 6 (GitHub auto-deploy)** is DONE: per-app, opt-in, webhook + PAT — a GitHub push webhook for Dockerfile/git apps and a CI deploy-hook for image apps. **Cluster-wide monitoring** is DONE: the sampler SSH-tunnels each worker's docker socket for per-node CPU/mem (control-plane + workers), shown on the Monitoring page with a node selector (migration 000027). **Still open:** Phase 8 (flexible state placement — local vs remote managed DB via DSN) and email/Slack notifications. The bot's HTTPS webhook + DB durability + private-image pull are all unblocked.

**Registries (private image pull):** org-scoped `registries` table (registry_url/username/password, plaintext) + nullable `applications.registry_id`. `docker.EncodeRegistryAuth(user,pass,url)` → `ServiceSpec.RegistryAuth` → `EncodedRegistryAuth` on `ServiceCreate/Update` (Swarm `--with-registry-auth`); the deployer's store loads+encodes the app's registry. `Engine.RegistryCheck` validates creds on create (engine-gated, so nil-engine tests skip it). UI: org Registries page (admin) + a registry select on app create/General. Real private pull verified on a host.

**Backups/S3 (Phase 4):** `destinations` (org-scoped S3 config: endpoint/bucket/region/keys, plaintext) + `backups` (per-postgres-DB: cron schedule, retention N, prefix, enabled, last_run/status). Dump path = `Engine.Exec` runs `pg_dump --clean --if-exists` inside the DB's container → gzip stream → S3 (aws-sdk-go-v2, path-style for MinIO) at `<prefix>/<app_name>/<ts>.sql.gz`; retention keeps newest N (count-based). Restore streams S3 → gunzip → `psql`. In-process `robfig/cron/v3` scheduler (`Scheduler.Reload` after any backup mutation, wired in main + via `Server.SetBackups`). `internal/backup` (s3.go/service.go/store.go/scheduler.go); destinations org-scoped + backups chain-checked (IDOR tests). S3 tested against a MinIO testcontainer (`testutil.NewMinio`); the live `pg_dump`/restore exec path is verified on a real host (no Swarm in unit tests). `runBackupNow`/`restoreBackup` run async on a detached context. See [`ROADMAP.md`](./ROADMAP.md) / [`PLAN.md`](./PLAN.md) and [`docs/superpowers/`](./docs/superpowers/) for the full trail.

**Advanced container settings:** nullable `applications` columns `memory_limit`/`cpu_limit`/`replicas`/`restart_condition`/`restart_max_attempts`/`healthcheck_*`; human units (`256m`/`0.5`/`30s`) parsed by `docker.ParseMemoryBytes`/`ParseNanoCPUs` → `ServiceSpec` `Resources.Limits` + `RestartPolicy` + `Healthcheck` in `buildSwarmSpec`; carried from the store into the deploy spec. UI: app "Advanced" tab (no reservations/placement/raw-JSON yet).

**App lifecycle controls:** Deploy/Reload/Rebuild/Stop buttons on the app General tab. Reload = `engine.ServiceRestart` (no rebuild); Rebuild = `EnqueueRebuild` (`docker build --no-cache`); Stop = `ServiceScale → 0`; Deploy brings it back up.

**Gateway route exposure:** per-domain `domains.exposed` + `domains.paths`. `traefik.AppLabels` skips non-exposed domains — **zero exposed → `traefik.enable=false` (overlay-only, internal)**; exposed + paths → `Host(...) && (PathPrefix(...) || …)` rule (anything else 404); `validPaths` guards against rule injection. **New apps are internal by default** (auto primary domain `exposed=false`, with a "not exposed" warning banner); existing domains were backfilled `exposed=true`. UI: Domains tab has a per-domain Exposed toggle + paths editor. The "who" axis (basic-auth / IP-allowlist) is done — see **Route protection** below.

**Route protection (basic-auth / IP-allowlist):** per-domain `domains.basic_auth_users` (htpasswd `user:bcrypthash`, newline-separated) + `domains.allowed_ips` (CIDR/IP, newline-separated; migration 000020). `traefik.AppLabels` attaches middlewares to the serving router (non-TLS `base`, TLS `base+"s"`; the redirect router is left unprotected) in order `ipallowlist.sourcerange` then `basicauth.users` — chained = AND. Admin-gated handlers (`addDomainBasicAuthUser`/`deleteDomainBasicAuthUser`/`setDomainAllowedIPs`) validate username-regex + `net.ParseCIDR`/`ParseIP` (canonicalized), bcrypt via `auth.HashPassword`; passwords/hashes are never logged or shown — logins only. UI: "Access protection" section on the Domains tab (exposed domains only). IDOR/admin-gate tests + a 4-lens adversarial review are green.

**App volumes/mounts + backup/restore:** `app_volumes` table (migration 000018) + a Volumes tab (admin); the deployer carries `Mounts` into `buildSpec` (fixes drift mount-loss on redeploy) and volumes are cleaned up on app/env/project delete. `docker.VolumeArchive`/`VolumeRestore` run a pinned-digest busybox sidecar (root, no network, ro archive) to tar a named volume → `volume_backups` + `internal/volume.VolumeService` (backup→gzip→S3 with count retention; restore quiesces the app first). A second `backup.Scheduler` drives cron; handlers are admin-gated with IDOR + cross-org destination checks. The live archive/restore path is verified on a real host (backup+restore round-trip of prod Readeck → MinIO).

**DB→app linking:** `app_db_links` table (migration 000019) links an app to a managed DB in the same environment → injects the live internal connection string into a chosen env var on **every** deploy (scheme `postgresql`/`postgres`/`redis`; overrides `env_text`; the password is pulled live via `secret.Dec`, never stored in `env_text`). UI: "Linked databases" section on the Environment tab (admin); links are cleaned up when the DB is deleted; IDOR/cross-org guard.

**Raw TCP/UDP published ports:** `app_ports` table (migration 000025: `host_port`/`container_port`/`protocol`, `UNIQUE(host_port, protocol)`) → `deploy.App.Ports` → `spec.Ports` (host publish mode; the `internal/docker` layer already supported TCP/UDP via `PortSpec.UDP`). Admin-gated `addAppPort`/`deleteAppPort` validate range 1..65535 + protocol ∈ {tcp,udp} and conflict-check the host port against both `app_ports` AND managed-DB `external_port` (for TCP); tenant chain-check + IDOR. UI: "Published ports" on the Advanced tab. Applied on the next deploy. Deferred: ingress (swarm LB) mode, port ranges, auto-pick, firewall/UFW.

**Build secrets/args + private git:** org-scoped `git_credentials` (PAT, token `secret.Enc`; migration 000021) + nullable `applications.git_credential_id`; private HTTPS clone authenticates via a `GIT_ASKPASS` helper (`builder.gitAuthSetup`) — the token is fed to git through env vars, never embedded in the clone URL/argv or written to the member-visible build log (`sanitizeGitURL` also strips any credentials before echoing). `applications.build_args` (non-secret → `--build-arg`) + `build_secrets` (`secret.Enc` → BuildKit `--secret` via `0600` temp files outside the build context, `DOCKER_BUILDKIT=1`, defer cleanup). Dockerfile source only. UI: org "Git credentials" page + per-app select + build_args/secrets editors on the Advanced tab (secrets masked, plaintext admin-only). Deferred: SSH deploy-keys.

**Multi-server (cluster):** Stage 1+2 merged to master, live-checked on 2 nodes. **Model: 1 control-plane Krill + N worker nodes** (NOT N installs). Engine swarm methods (`Nodes`/`NodeSetAvailability`/`NodeRemove`/`SwarmWorkerToken`/`ServiceTasks`/`NodeSetLabel`/`NodeDeleteLabel`); `cluster_nodes` table (migration 000022; SSH access, key `secret.Enc`) is a **global** (NOT org-scoped) infra resource gated by **`RequireInstanceAdmin`** (`users.is_admin`), NOT org-scoped RoleAdmin — see §4; `internal/cluster` SSH-joins workers (`docker swarm join`, accept-new host-key); the Nodes page (list + add-by-SSH / drain / remove) is instance-admin-only (non-operators get 404) + `KRILL_ADVERTISE_ADDR`; the control-plane node is guarded from drain/remove. Placement (migration 000023 `applications.placement_mode`/`placement_nodes`, `postgres_dbs`/`redis_dbs.node_hostname`; migration 000024 node labels): `ServiceSpec.Global`/`SpreadNodeID` in `buildSwarmSpec`; any/pin/global modes reconciled via `krill.place.<appID>` labels; a managed DB pins to a chosen node (`node.hostname==X`, node-local volume, apps reach it over overlay DNS). Deferred: stateful HA/replication, HA control-plane, network storage, per-replica hard pin, auto-migrate DB volume on node change.

**GitHub auto-deploy (Phase 6):** per-app, opt-in (`applications.auto_deploy`, default false; migration 000026), **webhook + PAT** (no OAuth/GitHub App). One per-app secret (`webhook_secret`, `secret.Enc`) serves both mechanisms; kept across disable→enable. Two PUBLIC endpoints registered before the `RequireAuth` group (auth is the secret, not a cookie; `csrfGuard` exempts the `/webhooks/` prefix): **Dockerfile/git apps** → `POST /webhooks/github/{appID}` verifies HMAC `X-Hub-Signature-256` (`webhook.VerifyHMAC`, constant-time), matches `ref` to `git_branch`, then `deployer.Enqueue(appID,"webhook")` → build+deploy (`ping`/unknown event/non-matching branch → 200 no-op; **bad sig → 404**, same as unknown/disabled/wrong source_type → so the endpoint never leaks which app IDs have auto-deploy enabled). **Image apps** → `POST /webhooks/deploy/{appID}` checks a Bearer/`?token=` secret (constant-time, empty stored secret rejected explicitly; bad token → 404), optional `?tag=` (`webhook.ValidTag` → `UpdateApplicationImage`), then re-pull+deploy; the CI calls it after `docker push`. The pure helper package is `internal/webhook` (`VerifyHMAC`/`ParsePushEvent`/`NewSecret`/`ConstantTimeEqual`/`ValidTag`, no GitHub SDK). Admin handlers `enableAutoDeploy`/`disableAutoDeploy`/`regenerateWebhookSecret` (admin-gated, tenant-chain) + a General-tab Auto-Deploy section (URL + masked secret reveal/copy + Regenerate, admin-only; webhook URL built from `Config.BaseURL()` ← `KRILL_PUBLIC_URL` or `KRILL_HOST`+scheme). **Same-tag re-pull fix:** `Engine.ResolveDigest` (registry `DistributionInspect`, no pull) pins image apps to `repo@sha256:…` in the deployer so a redeploy of an unchanged tag (`:latest`) actually pulls the new image (best-effort: `slog.Warn` + plain-tag fallback on error). Deferred: OAuth/GitHub App, repo/branch picker, auto-creating the webhook in GitHub, native GHCR `registry_package`, coalescing rapid pushes. See [`docs/superpowers/specs/2026-06-20-krill-phase6-github-autodeploy-design.md`](./docs/superpowers/specs/2026-06-20-krill-phase6-github-autodeploy-design.md).

## 2. Build / run / test (exact commands)

THE most important gotcha — DB/integration tests REQUIRE the Colima testcontainers env. Always run tests via `make test`. It auto-sets both env vars that Ryuk (testcontainers cleanup) needs on Colima's virtiofs:

```
DOCKER_HOST=unix://$HOME/.colima/default/docker.sock        # host socket path
TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock  # in-VM socket path
```

Without BOTH set, tests false-fail with a socket-mount error. NEVER report "Docker not running" without first trying this env. If you cannot use `make`, run the same command manually:

```
DOCKER_HOST=unix://$HOME/.colima/default/docker.sock \
TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock \
go test ./...
```

After editing any `.templ` or `.sql` file you MUST run `make generate` — generated code (`*_templ.go`, `internal/database/gen/*.sql.go`, and `internal/web/static/app.css`) is committed to the repo and the build uses it.

Commands:

| Task | Command |
|------|---------|
| Generate code (templ + sqlc + css) | `make generate` |
| Build binary | `make build` (→ `bin/krill`) |
| Run server | `make run` |
| Rebuild CSS (minified) | `make css` |
| Watch CSS | `make css-watch` |
| Run all tests (with Colima fix) | `make test` |
| Integration tests only | `make test-integration` (`-tags=integration`) |
| Start dev Postgres | `make db-up` |
| Stop dev Postgres | `make db-down` |
| `go mod tidy` | `make tidy` |
| Download Tailwind binary (first time) | `./tools/get-tailwind.sh` |
| Full E2E smoke test | `./scripts/e2e.sh` |

Local ports: app on `:18080`, Postgres on `55432` (the `.env` config used when the standard `8080`/`5432` are busy; `.env.example` uses `8080`/`5432`). Login: `admin@krill.local` / `changeme`.

Prereqs: Go 1.26.1, Docker/Colima running, Swarm initialized (`docker swarm init`), Tailwind v4.3.0 standalone binary at `./tools/tailwindcss` (no Node/npm). On startup `cmd/krill/main.go` runs embedded migrations, seeds the admin user + default org, bootstraps Traefik + the overlay network, then serves on `KRILL_LISTEN_ADDR`.

Required env vars: `KRILL_DATABASE_URL`, `KRILL_ADMIN_EMAIL`, `KRILL_ADMIN_PASSWORD`. Optional (with defaults): `KRILL_LISTEN_ADDR` (`:8080`), `KRILL_DOCKER_HOST`, `KRILL_BASE_DOMAIN` (`127-0-0-1.sslip.io`), `KRILL_NETWORK` (`krill-net`), `KRILL_HOST` (`localhost`), `KRILL_COOKIE_SECURE` (`false`), `KRILL_LOG_LEVEL` (`info`: debug/info/warn/error), `KRILL_LOG_FORMAT` (`text`: text/json), `KRILL_ACME_EMAIL` (Let's Encrypt contact; falls back to admin email), `KRILL_ACME_STAGING` (`false`), `KRILL_SECRET_KEY` (enables AES-256-GCM encryption-at-rest of stored secrets — DB passwords, registry/destination creds; empty = plaintext + a startup warning; legacy plaintext stays readable), `KRILL_CONVERGE_TIMEOUT` (`180s`; deploy convergence cap, auto-extended by a healthcheck's start_period), `KRILL_HEALTH_POLL_INTERVAL` (`30s`; how often the notification health watcher polls service state for app down/recovered alerts), `KRILL_TERMINAL_IDLE_TIMEOUT` (`15m`; closes an idle web-terminal session; `0` disables), `KRILL_METRICS_INTERVAL` (`30s`; how often the monitoring sampler records container stats), `KRILL_METRICS_RETENTION` (`48h`; how long metric history is kept before pruning), `KRILL_METRICS_NODE_TIMEOUT` (`10s`; per-worker timeout when the sampler SSH-tunnels to a worker node's docker socket for cluster-wide stats).

**Web terminal (Phase 7):** admin-only interactive `docker exec` into a running app container via xterm + WebSocket. `docker.ExecInteractive` returns an `ExecSession` (TTY, raw stream); the admin-gated `appTerminal` WS handler runs `pumpTerminal` (binary frames = stdin, text frames = `{"rows","cols"}` resize, session output = binary back), with `KRILL_TERMINAL_IDLE_TIMEOUT` reaping idle sessions. Tenancy via `loadAppCtx`; session I/O is never logged; same-origin WS. Terminal tab on the app page (`/bin/sh` + command override). The live `docker exec` path is verified on a real host (no Swarm in unit tests). See [`docs/superpowers/specs/2026-06-07-krill-phase7-web-terminal-design.md`](./docs/superpowers/specs/2026-06-07-krill-phase7-web-terminal-design.md).

**Monitoring (Phase 7 + cluster-wide):** **instance-admin-only** CPU/memory page (`/orgs/{id}/monitoring`, sidebar entry; the host-/cluster-wide view spans every tenant, so it is gated by `RequireInstanceAdmin` — NOT org-scoped RoleAdmin — and the sidebar/tab links show only for instance operators; non-operators get 404), now **cluster-wide**. A `metrics.Sampler` (`internal/metrics`) samples every `KRILL_METRICS_INTERVAL` into `metric_samples` (each row tagged with its `node`), pruned after `KRILL_METRICS_RETENTION`. The sampler drives a `metrics.ClusterSource` that collects the **control-plane node** (local daemon) plus **every `cluster_nodes` worker** in parallel: per worker it `cluster.DialVerified`s the stored SSH creds and forwards the remote `unix:///var/run/docker.sock` into a `docker.NewRemoteStats` client, reusing the same `statsCollector` (CPU% via `cpuPercent`, working-set memory; a per-connection `CPUCache` keyed by container ID — one per node so identical IDs don't mix). Each worker runs under `KRILL_METRICS_NODE_TIMEOUT`; an unreachable worker is warn-logged and skipped (the tick and other nodes proceed; the node renders **stale**). Per-node capacity (NCPU/MemTotal) is upserted into the `node_capacity` table each tick so `/monitoring/data` needs no SSH. `/monitoring/data?range=1h|6h|24h` returns a **per-node summary array** (`node`, cpu%, mem used/total, ncpu, containers, stale) + per-component series/rows tagged with `node` (series keyed by `(node, component)`), bucketed onto a shared grid (`metrics.GridTimes`/`BucketAvg`, nil = gap) and grouped by `metrics.Classify` (control/infra/app/db). The control-plane node is labelled `"control-plane"` (a friendly, stable name set in `cmd/krill/main.go`, matching the rest of the UI) rather than its raw Swarm hostname; workers use their `cluster_nodes.name` (e.g. `worker-1`). Each tick the sampler also `PruneCapacityExcept`s — dropping `node_capacity` for nodes no longer in the cluster (renamed/removed) so they stop showing as stale phantoms, while a still-listed-but-down worker stays (and renders stale). The client island `mountMonitoring` (`.k-mon`) draws uPlot CPU/mem charts + a per-node summary (one line per node) + a node-tagged grouped table (grouped by node header), and a **node selector** dropdown (All / per-node) that client-side-filters BOTH charts and table (series already carry `node`); the 10s poll timer is `window.__krillMonTimer`, cleared by `krillEnhance` on nav. The live `docker stats` path (local + SSH-tunnelled) is verified on a real host (no Swarm/SSH in unit tests). Migration `000027` adds `metric_samples.node` + `node_capacity`. See [`docs/superpowers/specs/2026-06-08-krill-phase7-metrics-design.md`](./docs/superpowers/specs/2026-06-08-krill-phase7-metrics-design.md) + [`docs/superpowers/specs/2026-06-21-krill-cluster-monitoring-design.md`](./docs/superpowers/specs/2026-06-21-krill-cluster-monitoring-design.md).

**Structured log viewer (Phase 7):** app + DB runtime logs render as a Dokploy-like table (time | level | message) instead of raw xterm. `ServiceLogs` requests docker `Timestamps`; `ParseLogLine` (`internal/server/logparse.go`, unit-tested) strips the docker RFC3339 prefix and detects the level (logfmt `level=` or a leading INFO/WARN/ERROR/DEBUG/TRACE/FATAL/SUCCESS token); `streamParsedLogsToWS` sends `{t,lvl,msg}` JSON frames. The client island `mountLogViewer` (`.k-logs[data-ws]`) renders color-coded rows with text search + a level filter (Debug/Info/Warn/Error). Deploy/build logs (`DeployLogHub`, `.k-term[data-ws]`) and the interactive Terminal (`.k-term[data-term-ws]`) still use xterm. See [`docs/superpowers/specs/2026-06-08-krill-phase7-log-viewer-design.md`](./docs/superpowers/specs/2026-06-08-krill-phase7-log-viewer-design.md).

**Notifications (Phase 7):** `internal/notify` sends Telegram alerts on failures + health transitions (deploy failed, backup failed, app down/recovered — no success spam). Org-scoped `notification_channels` (bot token encrypted via `secret`, masked in UI, never logged). Sources push events through tiny consumer-side interfaces (`deploy.Notifier` in `finish()`, `backup.Notifier` in `fail()`); a background `notify.Watcher` polls `ServiceStates` every `KRILL_HEALTH_POLL_INTERVAL` and alerts on healthy→down (debounce 2) / down→healthy transitions (in-memory state; an app never seen healthy stays silent — that case is covered by deploy-failure). Best-effort + async (detached ctx, 10s send timeout). Settings → Notifications (admin-only) + a "Send test message" button. See [`docs/superpowers/specs/2026-06-07-krill-phase7-notifications-design.md`](./docs/superpowers/specs/2026-06-07-krill-phase7-notifications-design.md).

**Secrets & i18n:** secrets are encrypted via `internal/secret` (`secret.Enc` on write, `secret.Dec` on read) at the store boundaries (dbservice store, db/registry/destination handlers, deploy store, backup store). UI masks them: DB connection strings render `type=password` + eye-reveal (`krillReveal`); env values are masked by default with a Show/Hide toggle (`krillEnvRevealToggle`). The UI is bilingual: `internal/web/i18n` has `en` + `ru` catalogs (keep both in sync — same keys); locale comes from the `krill_lang` cookie (set by `POST /lang` via the Settings language selector); `i18n.T`/`i18n.Tf` (printf) look it up.

**Domains/TLS (Phase 5):** the `domains` table (host UNIQUE, tls, is_primary) is the routing source of truth; `applications.domain` is the denormalized primary. `traefik.AppLabels(serviceName, []traefik.Domain, port, network)` emits per-domain routers — non-TLS on `web`, TLS on `websecure` with `tls.certresolver=le` plus a `web`→HTTPS redirect router (no global redirect). Domain CRUD re-applies labels via `engine.ServiceUpdateLabels` (service-level labels only → no container restart). Traefik bootstrap adds `:443` + the `le` HTTP-01 resolver + the persistent `krill-traefik-acme` volume at `/letsencrypt`. Real ACME issuance is verified manually (needs public DNS); locally TLS stays off and sslip.io domains serve plain HTTP.

**Logging:** structured `slog`, configured in `cmd/krill/main.go` (`setupLogging`). One access-log line per request comes from the `requestLogger` middleware (`internal/server/logging.go`); 5xx logs at error level. In handlers use `logFrom(r)` — a `*slog.Logger` pre-tagged with `request_id`/`user_id`/`org_id` — for error logs (before any 5xx response) and INFO audit logs (before the success redirect). Never log secrets (passwords, temp passwords, tokens, connection strings).

## 3. Critical facts that bite

- **Traefik is pinned to `v3.6.1`** (`internal/traefik/bootstrap.go`, const `TraefikVersion`). Versions ≤3.6.0 hardcode Docker API 1.24, which Docker Engine 29.x rejects ("client version 1.24 is too old"), breaking the Swarm provider and all routing. v3.6.1 auto-negotiates the API version. Traefik is configured via CLI args only (no `traefik.yml`); the only mount is the docker socket (read-only).
- **Tailwind v4 is CSS-first.** There is NO `tailwind.config.js` and NO `@tailwind` directives. Config lives in `internal/web/styles/input.css` via `@import "tailwindcss"`, `@source "../templates"`, `@theme { ... }`, and `@layer components`. Regenerate with `make css` or `make generate`. The output `internal/web/static/app.css` is a committed artifact (generated, not hand-edited).
- **templ component-on-its-own-line gotcha.** A `@Component(...)` call inline after text renders as literal `@Component` text. Put component calls on their own node:
  ```
  <div>
    @StatusBadge(status)
  </div>
  ```
- **Native `<dialog>` modals need `margin: auto`.** Tailwind preflight resets `margin: 0` on `<dialog>`, pinning modals to the top-left. The `.k-modal` class in `input.css` restores `margin: auto` to center them.
- **Confirm dialogs + log terminals: `app.js` loads ONCE in the layout `<head>` (deferred), NOT per-tab.** Destructive forms carry `hx-boost="false"` + `data-confirm` (server-rendered i18n message) and call `krillConfirm` (styled `#k-confirm` modal) — native `confirm()` is broken under hx-boost. Log viewers are `<div class="k-term" data-ws=...>` (xterm.js/addon-fit.js loaded per log-tab, lazy); `krillEnhance` (on `DOMContentLoaded`+`htmx:afterSettle`) auto-mounts any `.k-term[data-ws]:not([data-mounted])` and inits the env editor — so do NOT add inline `mountLogTerminal`/`krillEnvMode` calls or per-tab `app.js`. `.k-term` needs an explicit height (CSS) or FitAddon computes 0 rows on a boosted swap.
- **DB log feeds use negative feed IDs to avoid colliding with positive deployment IDs.** The `DeployLogHub` lives in `internal/deploy/logs.go`; the database feed-ID functions live in `internal/dbservice/service.go`: `pgFeedID(id) = -(id*2 + 1)`, `redisFeedID(id) = -(id*2 + 2)` (exported as `PgFeedID`/`RedisFeedID` for the deploy-log WS handler).
- **Named volume `<appName>-data` persists** for managed databases unless the user opts in via the "Destroy data" checkbox (`destroy_data=on`) on delete; only then is `engine.VolumeRemove()` called. Removal retries (`dbservice.removeVolume`) because right after `ServiceRemove` the volume is briefly "in use" while Swarm tears down the task container. **Deleting an environment or project destroys its managed-DB volumes** (`removeEnvDatabases` in `internal/server/project_handlers.go`, `destroy=true`) — otherwise the DB rows cascade-delete and the services/volumes would orphan with no UI to clean them.

## 4. Conventions (follow these)

- **Commit messages:** conventional-commits style (`feat(scope): ...`, `fix(scope): ...`, `test(...)`, `docs(...)`). HARD RULE: NO `Co-Authored-By` / Claude attribution trailers of any kind.
- **All UI strings go through `i18n.T(ctx, "key")`** with keys in the English catalog (`internal/web/i18n/en.go`). No raw user-facing literals in templates or handlers. The locale middleware (`WithLocale`) is currently a no-op (`en`); a second locale = a second map, no template changes.
- **Write everything in code in ENGLISH** — comments, `slog`/log messages, `fmt.Errorf`/`errors.New` strings, and `http.Error` messages. The codebase is English-only. The ONLY Russian that stays is the planning docs: `PLAN.md`, `ROADMAP.md`, and `docs/superpowers/**`. Do not introduce Russian in `.go`, `.templ`, `.sql`, `.sh`, `.css`, or config files.
- **Every app/db route must chain-check tenant ownership and 404 on mismatch.** Load org → project → environment (and db) and verify each FK matches its parent (`loadOrg` → `loadProject` → `loadEnvironment` → `loadApp`/`loadDBChain`). Mismatch returns `http.NotFound`. There are IDOR regression tests; keep them green.
- **Handlers must NOT swallow errors** — log via `slog.Error("context", "err", err)` or return 500. No silent ignores in delete/deploy/version handlers.
- **Only an owner may grant the owner role** (`updateMemberRole` in `internal/server/org_handlers.go`) — prevents admin self-escalation.
- **Deploy waits for convergence before marking done — baseline-relative.** Before `ServiceDeploy` the deployer snapshots the service's task IDs (`engine.ServiceProgress(name, nil)`), then polls `ServiceProgress(name, baseline)` until `Running >= Desired` counting ONLY tasks outside the baseline (`KRILL_CONVERGE_TIMEOUT`, 1s interval). Counting all tasks (old `ServiceState` behavior) would declare every redeploy converged instantly on the old StartFirst task. A `rollback_*` `UpdateState` fails the deploy ("update rolled back").
- **Build logs are bounded** — head (128 KB) + tail (128 KB) buffer with a `...[truncated N bytes]...` marker only when the middle is actually dropped (`internal/deploy/logs.go`).
- **RBAC is owner > admin > member** (`Role` int with `RoleMember`/`RoleAdmin`/`RoleOwner` and `AtLeast`), enforced by `RequireRole(min)` middleware (403 if role < min). Admin+ can manage projects/apps/dbs/members; members are read-only.
- **Instance-operator vs org-admin (security-critical):** org-scoped `RoleAdmin` is **self-grantable** — any authenticated user can `POST /orgs` and becomes the new org's `owner`. So **global infrastructure (cluster nodes, the host-wide monitoring view) is gated by `RequireInstanceAdmin`**, backed by the instance-level flag `users.is_admin` (migration 000028), NOT by org-scoped RoleAdmin. Only the seeded `KRILL_ADMIN_EMAIL` user is promoted to `is_admin=true` on startup (`SeedAdmin`, idempotent); everyone else defaults false. `WithInstanceAdmin` loads the flag once per authed request into the ctx; `RequireInstanceAdmin` 404s non-operators (no capability disclosure). Do NOT gate a global/cross-tenant resource on `RequireRole` — use `RequireInstanceAdmin`.
- **Login hardening:** the unknown-email path runs a dummy bcrypt (`auth.dummyHash`) so it costs the same as a real check (no user-enumeration timing oracle); `POST /login` is per-source-IP rate-limited (`internal/server/ratelimit.go`, 10/min).
- **App mutations and DB secrets are admin-gated** (2026-06-06 hardening): the app POST routes (deploy/rebuild/reload/stop/env/advanced) and the DB backup download/objects routes sit inside a `RequireRole(RoleAdmin)` group in `server.go`; plaintext connection-string display is admin-only too. Members are read-only viewers — no deploys, no DB dumps/creds.
- **`external_port` is validated and conflict-checked** — `strconv.Atoi` + range `1..65535` → 400 on bad input; pre-check existing ports → 400 on duplicate.
- **Temp passwords flow via HttpOnly flash cookie** (`krill_flash_pw`), never in the URL; the template reads it once then clears it.
- **Unique-violation detection uses `errors.As(*pgconn.PgError)` + code `23505`** (`mapUniqueErr` in `internal/org/service.go`), not string matching.

## 5. Architecture map

Runtime topology: a single Go binary (HTTP on `:8080`/`:18080`) holds all state in PostgreSQL (pgxpool) and drives a single-node Docker Swarm via the Docker API. Traefik (a Swarm service on host `:80`) watches the Swarm API and routes by `Host` header to app/db services on the `krill-net` overlay. One deployment worker goroutine serializes all build/deploy jobs.

Packages:

- **`cmd/krill`** — entry point: load config → migrate → pgxpool + sqlc → seed admin/default org → wire services → bootstrap Traefik+network → start chi server → graceful shutdown.
- **`internal/config`** — env parsing via caarlos0/env (`Config`, `Load()`).
- **`internal/server`** — chi router, middleware chain, all handlers; path-scoped multi-tenant routes. Tenancy chain-checks `loadOrg`/`loadProject`/`loadEnvironment`/`loadApp` live in `context.go`; `loadDBChain` lives in `db_handlers.go`.
- **`internal/auth`** — sessions, bcrypt, RBAC (`Role` member<admin<owner, `AtLeast`), cookie `krill_session` (`CookieName`, `SessionTTL` = 7 days); middleware `RequireAuth`, `RequireOrgMember`, `RequireRole`, `WithInstanceAdmin`/`RequireInstanceAdmin` (instance-operator gate for global infra, backed by `users.is_admin`); ctx helpers `UserID`/`OrgID`/`RoleOf`/`IsInstanceAdmin`.
- **`internal/org`** — org/project/env/app/member CRUD, `Slugify`, `ErrNotFound`/`ErrSlugTaken`, `mapUniqueErr`.
- **`internal/docker`** — Swarm API wrapper. **`Engine` interface methods:** `NetworkEnsure(ctx,name)`, `ServiceDeploy(ctx,ServiceSpec)`, `ServiceRemove(ctx,name)`, `ServiceState(ctx,name)→ServiceState`, `ServiceProgress(ctx,name,excludeTaskIDs)→ServiceProgress` (baseline-relative convergence: new-task Running/Failed + swarm `UpdateState` for rollback detection), `ServiceLogs(ctx,name,follow)→io.ReadCloser`, `ServiceScale(ctx,name,replicas uint64)`, `ImagePull(ctx,ref,out)`, `VolumeRemove(ctx,name)`. Helpers: `ServiceName(appID)→"krill-<id>"`, `BuildImageTag(appID,deployID)→"krill-<id>:<deployID>"`. Rolling update is parallelism=1, StartFirst (zero-downtime), rollback-on-failure; DNSRR for DBs, VIP for apps.
- **`internal/deploy`** — `Deployer` (queue + 1 worker, 10-min job timeout, 90s convergence poll), `DeployLogHub` (in-memory head+tail buffer + WS subscribers), `Store` interface, status values (`idle`/`deploying`/`running`/`error`), `DeriveStatus`, `StartLogCleanup` (truncates logs >1h old).
- **`internal/builder`** — `Builder` interface; `gitBuilder` does shallow `git clone --depth=1` + `docker build`; `ValidateBuildRequest` guards against flag injection and path traversal.
- **`internal/dbservice`** — managed Postgres/Redis lifecycle over Engine+Store; service specs (DNSRR, named volume `<appName>-data`, manager constraint) in `spec.go`; connection-string builders (internal overlay DNS / external host port).
- **`internal/traefik`** — `TraefikVersion`, `TraefikSpec(network)`, `Bootstrap(ctx,engine,network)` (idempotent), `AppLabels(...)` generating `traefik.http.routers.*`/`services.*` labels.
- **`internal/web`** — embedded static (`Static()` in `embed.go`), i18n (`WithLocale`, `T`, `en` catalog), templ templates (`layout`, `login`, `orgs`, `org_dashboard`, `project`, `app_detail`, `database_detail`, `deployments`, `members`, `status_badge`, plus shared `ui/components`).
- **`internal/database`** — `RunMigrations(dsn)` (embedded, idempotent, ignores `ErrNoChange`), sqlc-generated `gen/` (read-only).
- **`internal/testutil`** — `NewTestDB(t)` spins an ephemeral `postgres:16-alpine` testcontainer, migrates, returns a pool with cleanup.

## 6. Data model

Tables (BIGSERIAL PKs unless noted): `users`, `sessions` (PK token), `organizations`, `members`, `projects`, `environments`, `applications`, `deployments`, `postgres_dbs`, `redis_dbs`, `domains`, `backups`, `destinations`, `registries`, `notification_channels`, `metric_samples`, `app_volumes`, `volume_backups`, `app_db_links`, `git_credentials`, `cluster_nodes` (global, not org-scoped), `app_ports`, `node_capacity` (per-node CPU/mem capacity for cluster monitoring). Migrations: `000001_init`, `000002_org_hierarchy`, `000003_dockerfile_deployments`, `000004_managed_databases`, `000005_domains`, `000006_backups`, `000007_registries`, `000008_app_advanced` (advanced container columns on `applications`), `000009_domain_exposure` (`domains.exposed` + `domains.paths`, existing rows backfilled `exposed=true`), `000010_external_port_unique` (partial UNIQUE index on `external_port`), `000011_owner_fk_ondelete` (`organizations.owner_id` FK → ON DELETE RESTRICT), `000012_app_command` (nullable `applications.command` — container CMD override), `000013_app_env_text` (`applications.env_text` TEXT — raw order-preserving KEY=VALUE lines for the editor), `000014_drop_app_env` (drops the redundant JSONB `env` map — `env_text` is now the single source; the deploy map is derived at runtime via `deploy.parseEnvText`), `000015_notification_channels` (org-scoped Telegram notification config: bot token encrypted, per-category toggles deploy/backup/health, `UNIQUE(org_id, type)`), `000016_metric_samples` (monitoring history: `component`/`cpu_pct`/`mem_bytes`/`mem_limit_bytes`/`ts`, indexed on `ts` and `(component, ts)`), `000017_fk_indexes` (FK-column indexes for the org dashboard / per-env listings), `000018_app_volumes` (`app_volumes` — app named-volume mounts), `000019_app_db_links` (`app_db_links` — app↔managed-DB connection-string injection), `000020_domain_protection` (`domains.basic_auth_users` + `domains.allowed_ips`), `000021_build_credentials` (`git_credentials` + `applications.git_credential_id`/`build_args`/`build_secrets`), `000022_cluster_nodes` (`cluster_nodes` — global SSH worker-node registry), `000023_node_placement` (`applications.placement_mode`/`placement_nodes`, `postgres_dbs`/`redis_dbs.node_hostname`), `000024_node_labels` (node-label bookkeeping for placement), `000025_app_ports` (`app_ports` — raw TCP/UDP published ports, `UNIQUE(host_port, protocol)`), `000026_app_autodeploy` (`applications.auto_deploy` BOOLEAN + `webhook_secret` TEXT — per-app GitHub auto-deploy toggle + HMAC/deploy-hook secret), `000027_cluster_metrics` (`metric_samples.node` TEXT + index `(node, component, ts)`; `node_capacity` table — per-node NCPU/MemTotal for cluster-wide monitoring), `000028_user_is_admin` (`users.is_admin` BOOLEAN NOT NULL DEFAULT false — instance-operator flag gating global infra via `RequireInstanceAdmin`; the seeded `KRILL_ADMIN_EMAIL` user is promoted on startup).

Tenancy chain (FK-enforced, ON DELETE CASCADE): `organizations` → `projects` → `environments` → `applications` / `postgres_dbs` / `redis_dbs`. `members` joins users↔orgs with `UNIQUE(org_id,user_id)` and role CHECK (`owner`/`admin`/`member`).

Key facts:
- For managed DBs, `app_name` is UNIQUE and is simultaneously the Swarm **service name = internal DNS hostname = volume name prefix** (`<appName>-data`).
- `external_port` is a nullable `*int32` (sqlc `emit_pointers_for_null_types: true`); conflicts checked via `CountPostgresByExternalPort` / `CountRedisByExternalPort` and enforced by a partial UNIQUE index (`WHERE external_port IS NOT NULL`, migration 000010).
- DB **credentials/passwords are stored plaintext** (no encryption at rest).
- `applications.env_text` (TEXT) is the SINGLE source for env vars — raw, ORDER-PRESERVING `KEY=VALUE` lines (the editor shows `c.App.EnvText`; no re-sorting). The deploy map is derived at runtime (`deploy.parseEnvText`); the old JSONB `env` map column was dropped (migration 000014). `parseEnv` (server) returns the map **and** duplicate keys → `saveEnv` rejects dupes. `applications.domain` has a UNIQUE index; `source_type` CHECK (`image`/`dockerfile`). Advanced container columns (migration 000008): nullable `memory_limit`/`cpu_limit` (TEXT, human units), `replicas` (default 1), `restart_condition` CHECK (`any`/`on-failure`/`none`), `restart_max_attempts`, and `healthcheck_*` (cmd/interval/timeout/retries/start_period). Nullable `command` (migration 000012, TEXT) is an optional container CMD override — `docker.SplitCommand` whitespace-splits it into `ServiceSpec.Args` (overrides the image CMD, keeps ENTRYPOINT; e.g. `start-dev` for Keycloak). Edited on the Advanced tab via `saveAdvanced`.
- `domains` (migration 000009) has `exposed` (BOOLEAN, default false — new domains are internal-only) and `paths` (TEXT, comma-separated path prefixes; empty = whole host) driving Traefik route exposure.
- `deployments` is append-only history: `status` CHECK (`running`/`done`/`error`), `trigger` CHECK (`manual`/`webhook`/`schedule`), index `(application_id, started_at DESC)`; `ClearOldDeploymentLogs` empties the `log` field for rows finished >1h ago (keeps metadata); `ListDeploymentsByApplication` returns last 50.
- All `timestamptz` map to Go `time.Time`. sqlc config (`sqlc.yaml`): schema `internal/database/migrations`, queries `internal/database/queries`, package `db`, out `internal/database/gen`, `pgx/v5`, `emit_interface`/`emit_json_tags` on.

## 7. Dev workflow in this repo

Brainstorm → spec (`docs/superpowers/specs/`, date-prefixed) → plan (`docs/superpowers/plans/`, date-prefixed) → subagent-driven execution.

- Subagents run STRICTLY SEQUENTIALLY (parallel execution reordered/duplicated tool calls — see Gotchas).
- Subagents do NOT commit on master; the harness blocks it. Only the controller commits.
- Always verify with `make test` before committing.

## 8. Gotchas / lessons (don't repeat these)

- **Parallel subagents reorder/duplicate tool calls** — run subagents sequentially.
- **Traefik API mismatch → routing breaks** when not pinned to ≥v3.6.1 against Docker Engine 29.x (see §3).
- **`StatusBadge` (and any templ component) rendered as literal text** when placed inline after text on the same line — give it its own node.
- **Modals pinned top-left** because Tailwind preflight zeroes `<dialog>` margins — use `.k-modal` (`margin: auto`).
- **CHECK-constraint violations in tests** when omitting `SourceType` (must be `image` or `dockerfile`) or supplying an out-of-set `status`/`trigger`/`role`. Always set CHECK-constrained columns to valid values in fixtures.
- **Tests false-fail with a socket-mount error** off the Colima env — always use `make test` (see §2).

## 10. Docker & CI

- **`Dockerfile`** — multi-stage: `golang:1.26.1-alpine` builder → `CGO_ENABLED=0` static binary → `gcr.io/distroless/static-debian12:nonroot` (~25 MB, runs as UID 65532). It relies on the COMMITTED generated files (no `make generate` in-image); migrations (`//go:embed migrations/*.sql`) and static assets (`//go:embed all:static`) are embedded, so the final image is binary-only. Build locally: `docker build -t krill:local .`.
- **`.github/workflows/ci.yml`** — push (all branches) + PR: build/vet/test (testcontainers works on the runner's native Docker — do NOT add the Colima socket override here), a no-push Docker build, and a generated-drift check (`make generate` + `git diff --exit-code`).
- **`.github/workflows/release.yml`** — `v*.*.*` tag (or `workflow_dispatch`): multi-arch buildx → push to `ghcr.io/${{ github.repository_owner }}/krill` → GitHub Release on tag pushes. On a tag it ALSO cross-compiles static binaries (`krill-linux-amd64`/`krill-linux-arm64`, `CGO_ENABLED=0`, committed generated files) + a `checksums.txt` and attaches them as Release assets — these are what `install.sh` downloads. Uses `GITHUB_TOKEN`; needs `permissions: packages: write` + `contents: write`. First GHCR push is private — make the package public if anonymous pulls are wanted.
- **`install.sh`** (repo root) — VPS one-liner (`curl -sSL …/master/install.sh | sudo sh`): host binary + systemd (NOT a container), idempotent (re-run = upgrade). Installs Docker if missing → `swarm init` → loopback-only `krill-postgres` container for state → downloads the checksum-verified release binary (fail-closed: missing `checksums.txt`/entry aborts unless `KRILL_SKIP_VERIFY=1`) → generates `/etc/krill/krill.env` (admin pw + `KRILL_SECRET_KEY` created once, preserved on re-run; `KRILL_COOKIE_SECURE=false` for first HTTP login) → `krill.service`. Variant A (host binary) was chosen over a Swarm-service install to avoid the nonroot-socket and self-exposure chicken-and-egg. See [`docs/superpowers/specs/2026-06-09-krill-installer-design.md`](./docs/superpowers/specs/2026-06-09-krill-installer-design.md).
- After changing the build/embed setup, re-verify by actually building the image (`docker build .`) and confirming it still runs (`docker run --rm krill:local` should fail fast on the missing `KRILL_DATABASE_URL`).
