# Cluster, topology and monitoring

Worker nodes and placement, node-aware exec, the topology map, the environment canvas (systems), and cluster-wide monitoring.

## Multi-server (cluster)

Stage 1+2 merged to master, live-checked on 2 nodes. **Model: 1 control-plane Krill + N worker nodes** (NOT N installs). Engine swarm methods (`Nodes`/`NodeSetAvailability`/`NodeRemove`/`SwarmWorkerToken`/`ServiceTasks`/`NodeSetLabel`/`NodeDeleteLabel`); `cluster_nodes` table (migration 000022; SSH access, key `secret.Enc`) is a **global** (NOT org-scoped) infra resource gated by **`RequireInstanceAdmin`** (`users.is_admin`), NOT org-scoped RoleAdmin — see [the instance-operator rule](security.md#instance-operator-vs-org-admin-security-critical); `internal/cluster` SSH-joins workers (`docker swarm join`, accept-new host-key); the Nodes page (list + add-by-SSH / drain / remove) is instance-admin-only (non-operators get 404) + `KRILL_ADVERTISE_ADDR`; the control-plane node is guarded from drain/remove. Placement (migration 000023 `applications.placement_mode`/`placement_nodes`, `postgres_dbs`/`redis_dbs.node_hostname` at the time — carried forward as `db_instances.node_hostname` by migration 000029; migration 000024 node labels): `ServiceSpec.Global`/`SpreadNodeID` in `buildSwarmSpec`; any/pin/global modes reconciled via `krill.place.<appID>` labels; a DB instance pins to a chosen node (`node.hostname==X`, node-local volume, apps reach it over overlay DNS). Deferred: stateful HA/replication, HA control-plane, network storage, per-replica hard pin.

## Topology (visual cluster map)

a read-only, org-scoped page (`RequireRole(RoleAdmin)`, NOT `RequireInstanceAdmin` — it only ever exposes the org's own apps/DB instances/links) at `/orgs/{id}/topology` (+ `/topology/data` JSON) draws node lanes (control-plane + workers from `engine.Nodes`) holding the org's apps and DB instances by actual placement, resolved via the new `docker.Engine.Tasks` method (one `ServiceList`+`NodeList`+`TaskList` sweep for every service's node, instead of a per-service `ServiceTasks` call). Logical databases render as chips inside their Postgres instance's box; `app_db_links` draw as colored threads (color = target engine Postgres/Redis; a cross-node thread — app and DB on different nodes — renders thicker + dashed). **v2** (2026-07-05) adds: an **Ingress lane** (Internet → the `krill-traefik` gateway service → exposed app, edge labelled with the domain from `ListDomainsByApplication`), directional arrows (SVG markers) on every edge, connection **detection from raw `env_text` DSNs** (`topology.DetectEnvLinks` scans each app's parsed env for `<db_instance_app_name>:5432`/`:6379`, matching down to the logical database when a `/<db_name>` suffix is present) alongside the modeled `app_db_links` (deduped — a modeled link wins over a detected one to the same target), and collapsing of multiple per-field links from one app to the same DB into a single thread. Pure `internal/topology` package (`Build`, `DetectEnvLinks`, graph types `Graph`/`GNode`/`GService`/`GDB`/`GLink`) — no DB/docker access itself, fed by a thin adapter in `internal/server/topology_handlers.go`. **No migration, no new SQL query** (v2 only adds an exported `traefik.ServiceName` const, replacing an inline literal). Since the 2026-11-22 UI redesign the page is drawn on the server from the same graph (`topoView` in `topology_handlers.go`: an ingress lane, one lane per node, cards with `data-to`/`data-detected`, a `?project=` filter) and the client only draws the wires (`mountWiredMap` in `app.js`, shared with the canvas and the nodes page); `/topology/data` still serves the JSON. See `docs/superpowers/specs/2026-07-04-krill-topology-graph-design.md` / `docs/superpowers/plans/2026-07-04-krill-topology-graph.md` (v1) and `docs/superpowers/specs/2026-07-05-krill-topology-v2-ingress-design.md` / `docs/superpowers/plans/2026-07-05-krill-topology-v2-ingress.md` (v2).

## Systems

*(2026-11-06)*

env-scoped `systems` + `system_members` (migration 000058; `application_id` is the key, so one system per app; both FKs CASCADE, so deleting a system or an app only drops membership). The environment page builds `topology.BuildEnvView` (pure, `internal/topology/env.go`) from a thin adapter (`Server.envView`, `internal/server/system_handlers.go`): modeled DB links, bucket links and `DetectEnvLinks` DSN detection (detected uses are marked, a modeled link wins), and `CountResourcesByInstance` for the "shared" flag (a resource is shared when used outside the system or its server hosts other databases/buckets). Since the 2026-11-22 UI redesign the environment page is a canvas: `topology.LayoutCanvas` (pure, `internal/topology/canvas.go`) places each system as a framed group (apps left, the resources they use right) and everything else in a "not in a system" group; `Server.canvasFor` (`internal/server/env_pages.go`) turns that into cards placed on the nodes their tasks run on, and `mountWiredMap` in `app.js` draws the links (dashed for `AppView.Detected`), the node filter, zoom and pan. App and logical-database cards keep the `cs-app-<id>`/`cs-ldb-<id>` state ids, so the `envStatuses` OOB refresh (polled every 10s) still works. Systems are managed on the environment's settings page. See `docs/guides/systems.md`.

## Monitoring

*(Phase 7 + cluster-wide)*

**instance-admin-only** CPU/memory page (`/orgs/{id}/monitoring`, sidebar entry; the host-/cluster-wide view spans every tenant, so it is gated by `RequireInstanceAdmin` — NOT org-scoped RoleAdmin — and the sidebar/tab links show only for instance operators; non-operators get 404), now **cluster-wide**. A `metrics.Sampler` (`internal/metrics`) samples every `KRILL_METRICS_INTERVAL` into `metric_samples` (each row tagged with its `node`), pruned after `KRILL_METRICS_RETENTION`. The sampler drives a `metrics.ClusterSource` that collects the **control-plane node** (local daemon) plus **every `cluster_nodes` worker** in parallel: per worker it `cluster.DialVerified`s the stored SSH creds and forwards the remote `unix:///var/run/docker.sock` into a `docker.NewRemoteStats` client, reusing the same `statsCollector` (CPU% via `cpuPercent`, working-set memory; a per-connection `CPUCache` keyed by container ID — one per node so identical IDs don't mix). Each worker runs under `KRILL_METRICS_NODE_TIMEOUT`; an unreachable worker is warn-logged and skipped (the tick and other nodes proceed; the node renders **stale**). Per-node capacity (NCPU/MemTotal) is upserted into the `node_capacity` table each tick so `/monitoring/data` needs no SSH. `/monitoring/data?range=1h|6h|24h` returns a **per-node summary array** (`node`, cpu%, mem used/total, ncpu, containers, stale) + per-component series/rows tagged with `node` (series keyed by `(node, component)`), bucketed onto a shared grid (`metrics.GridTimes`/`BucketAvg`, nil = gap) and grouped by `metrics.Classify` (control/infra/app/db). The control-plane node is labelled `"control-plane"` (a friendly, stable name set in `cmd/krill/main.go`, matching the rest of the UI) rather than its raw Swarm hostname; workers use their `cluster_nodes.name` (e.g. `worker-1`). Each tick the sampler also `PruneCapacityExcept`s — dropping `node_capacity` for nodes no longer in the cluster (renamed/removed) so they stop showing as stale phantoms, while a still-listed-but-down worker stays (and renders stale). The client island `mountMonitoring` (`.mon`) draws CPU and memory per node as SVG lines (the components' series summed per node, as % of the node), a column per node with its containers (rows of the org's own apps and servers link to them via `monRow.Href`), and a node switch that filters both; uPlot is gone. The 10s poll timer is `window.__krillMonTimer`, cleared by `krillEnhance` on nav. The live `docker stats` path (local + SSH-tunnelled) is verified on a real host (no Swarm/SSH in unit tests). Migration `000027` adds `metric_samples.node` + `node_capacity`. See `docs/superpowers/specs/2026-06-08-krill-phase7-metrics-design.md` + `docs/superpowers/specs/2026-06-21-krill-cluster-monitoring-design.md`.

## Pitfalls

### Exec operations (logical-DB provisioning, pg_dump backups, restore, web terminal) are node-aware

`Engine.Exec` and `ExecInteractive` locate the running task's node (`runningContainerID` → NodeID) and via an injectable `RemoteClientProvider` (wired in `cmd/krill/main.go`) select the docker client: local for control-plane, or remote via SSH tunnel to a worker's docker socket (`docker.NewRemoteClient` + `cluster.DialVerified`, lookup `cluster_nodes` by `swarm_node_id`). `cluster_nodes` holds only workers → a non-worker task = control-plane = local. Provider nil (tests / single-node) → always local. `ServiceLogs` already worked cross-node (Swarm API, not exec). **Docker-client opt-order gotcha (bit us on the live 3-node cluster):** in `NewRemoteClient`/`NewRemoteStats`, `client.WithHost("unix://…")` MUST come BEFORE `client.WithDialContext(dial)`. `WithHost` for a unix host calls `sockets.ConfigureTransport`, which OVERWRITES `transport.DialContext` with a local-socket dialer — so if `WithDialContext` runs first, the tunnel dialer is silently clobbered and the "remote" client talks to the LOCAL daemon (symptom: worker exec fails "No such container", and cluster monitoring silently reported the manager's stats as the worker's). Set the tunnel dialer LAST.
