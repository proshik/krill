# Agent API (MCP + REST)

The agent-facing API: operations, token auth, the MCP session binding, and provisioning.

## Agent API — MCP + REST

*(2026-08-13)*

twelve agent-facing operations over apps that **already exist** (plus four creating ones since 2026-11-21, see Provisioning below), living in one transport-agnostic service layer (`internal/api`, tenancy + level gate inside) with two thin adapters: **REST** `/api/v1/*` (`internal/server/api_handlers.go`) for CI/scripts and **MCP** streamable HTTP at `/mcp` (`internal/mcpsrv`, `github.com/modelcontextprotocol/go-sdk` v1.8.0; its DNS rebinding guard is off via `DisableLocalhostProtection` — it would 403 a same-host reverse proxy forwarding a domain to 127.0.0.1, and the bearer token already rules out a rebound browser page). Read tools/routes: `krill_whoami`, `krill_list_apps`, `krill_app_status`, `krill_app_logs`, `krill_deployments`, `krill_deployment_status`, `krill_list_env` (`GET /api/v1/whoami|apps|apps/{app}|apps/{app}/logs|apps/{app}/deployments|deployments/{id}|apps/{app}/env`). Write: `krill_deploy`, `krill_rebuild`, `krill_reload`, `krill_stop`, `krill_set_env` (`POST /api/v1/apps/{app}/{deploy|rebuild|reload|stop|env}`). **There are no destructive operations at all** — nothing creates or deletes an org/project/environment/app/DB/domain/volume, and there is no `docker exec`/terminal; the blast radius is bounded by the surface, not by a permission matrix (a list of twelve is checkable by eye). `{app}` is a numeric id or a `project/environment/app` path (`api.Service.resolveApp`; cross-org ⇒ **404, never 403**).

**Auth:** org-scoped bearer tokens in `api_tokens` (**migration 000040**) — `krill_pat_<32B base64url>`, stored as SHA-256 + an 8-char lookup prefix (index NOT unique; candidates are compared constant-time), plaintext shown **once** via the `krill_flash_token` one-shot cookie and unrecoverable. `Identity.CanWrite()` = token `level` ∩ the owner's **live** role (`>= RoleAdmin`), re-resolved by `Authenticator.Authenticate` on every request — demoting or removing the member kills their write token instantly, with no revocation step. `RequireAPIToken` (`internal/server/api_middleware.go`) accepts the token **only** from `Authorization: Bearer` (never `?token=` — query strings land in proxy logs/history), rate-limits **60 req/min per token** (429 + `Retry-After`), and stashes the Identity via `api.WithIdentity` — which is why the identity ctx key lives in `internal/api` (`internal/mcpsrv` must not import `internal/server`; that would cycle). Both surfaces are registered BEFORE the `RequireAuth` group and exempted from `csrfGuard` (an MCP client sends no `Origin`); the ONE `mcpsrv` handler instance is mounted at both `/mcp` and `/mcp/*` (it owns the `Mcp-Session-Id` session table — two instances would lose sessions).

**An MCP tool must NOT read the Identity from its handler's `ctx` (2026-09-23):** in a stateful go-sdk session every handler runs on the context of the request that opened the session (`initialize`), so `ctx` kept the first request's identity (and request id) for the session's whole life — a demotion never reached an open session, and another valid token presented with a leaked `Mcp-Session-Id` ran as the session's owner. `mcpsrv.Handler` now lifts each request's Identity into an SDK `auth.TokenInfo` (`bindSession`, via `auth.RequireBearerToken` — the SDK's context key is unexported, and it verifies nothing new), tools read it from `req.Extra.TokenInfo` (`callerIdentity`), and `TokenInfo.UserID = "token:<id>"` binds the session to the token that opened it, so the SDK refuses any other token with 403 "session user mismatch" (`TestMCPSessionSeesDemotion`/`TestMCPSessionRejectsAnotherToken` in `internal/server`). REST has no sessions, so it never had this. **`KRILL_AGENT_API_ENABLED` (default true) gates BOTH surfaces** — false leaves the authenticator unwired and `/api/v1` 404s too. (It was `KRILL_MCP_ENABLED` until 2026-08-13; renamed because it never gated MCP alone.) Deploys are **async** (`{deployment_id, status}` → poll `krill_deployment_status`); logs are bounded (runtime tail default 200 / max 1000, build-log tail ~8 KB); **`krill_list_env` returns names + source (`literal`/`db-link`) and NEVER values** (everything an agent reads reaches its model provider); `krill_set_env` edits a single `env_text` line (order/comments preserved, duplicate key ⇒ conflict) and does **not** redeploy. Errors are `api.Error{Code,Message}` → HTTP status (REST) / `isError` text (MCP); internal errors never leak `err.Error()` (generic text + `request_id`). Every write logs an INFO audit line with `token_id`/`user_id` (never the token, never an env value); at startup a non-`https` public URL with the API enabled logs a warn. UI: Settings → **API tokens** (`/orgs/{id}/api-tokens`; create is admin-gated, list/revoke only need membership and only ever touch the caller's own tokens).

**Provisioning (2026-11-21):** four creating operations — `krill_create_database` / `POST /api/v1/environments/{project}/{env}/databases`, `krill_create_app` / `…/apps`, `krill_add_domain` / `POST /api/v1/apps/{app}/domains`, `krill_link_database` / `…/db-links` — for a third token level `provision` (migration 000063 widens `api_tokens_level_check`; `Identity.CanProvision` = provision ∩ live admin; `CanWrite` accepts provision too; the previous release treats a provision token as read-only, never stronger). Still nothing deletes or changes an existing resource. `api.Service` owns the gate (`requireProvision` BEFORE resolving anything, like `requireWrite`) and tenancy (`resolveEnv` by project/environment NAMES, 404 outside the org); the work is `server.apiProvisioner` (wired in `SetAPI`), which reuses the UI's building blocks — `hostshare.CreateApplication/Add/UpdatePaths/SetTLS`, `dbservice.ProvisionLogicalDB` with the row-rollback, `syncAppLabelsCtx`, `linkVarTakenCtx` (ctx variants of the UI helpers) — so an API-created resource matches a UI-created one. Idempotency is by natural key (env+name, app+host, app+var): identical repeat → existing with `created:false` (a domain repeat also re-syncs labels, recovering a failed first sync); different settings → `409`. Create-app is image-only and never deploys; its primary domain defaults to `<name>.<base domain>`, internal. MCP argument structs embed the `api.*Input` REST bodies; `TestProvisionToolSchemasAreFlat` pins that the SDK flattens them. Review hardening (same date): each operation holds an `oplock` on its natural key (`api-provision:<kind>:<scope>:<name>`) from lookup to write, and a db-link to a logical database also waits on that database's key, so concurrent identical requests and a link racing a still-provisioning database are both safe (one process); the database is provisioned and rolled back on a context detached from the request (`provisionTimeout`); create-app writes the app, primary-domain settings and registry in ONE transaction under the host reservation (`hostshare.CreateApplicationConfigured`); the app repeat check includes the tag; `DomainInput.TLS` is `*bool` — on a shared host an omitted value inherits, an explicit different one is 409; a name-or-id reference matching one resource by name and another by id, and an environment path two projects share, are refused as ambiguous; `domains`/`db-links` are peeled off as verbs only on POST (`postOnlyVerbs`), so apps with those names keep their GET status route. **`dbservice.ProvisionLogicalDB` now checks `pg_database`/`pg_roles` first and returns `ErrObjectsExist` without touching anything** — before, a collision with a database Krill did not create (restored by hand from a dump) failed CREATE and the compensating `DROP DATABASE … WITH (FORCE)` deleted it (UI and API alike); psql runs with `-X`. `syncAppLabelsCtx` skips the Swarm write when the labels already match (an unchanged ServiceUpdate resets UpdateStatus, which a converging deploy reads as done). The 000063 down migration maps provision tokens to `read`, not `write`. `KRILL_MCP_SESSION_TIMEOUT` (default `30m`, `0` disables) closes an idle MCP session and frees its goroutine: a session ends explicitly only on `DELETE /mcp`, which a crashed agent or a finished CI job never sends.
