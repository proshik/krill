# Krill internals

Reference notes on how each Krill feature is built: invariants, file and function names, and
the reasons behind non-obvious choices. [`AGENTS.md`](../../AGENTS.md) holds the rules that apply
everywhere; these files hold the detail for one area each. Read the relevant file before
changing that area, and update it in the same change when you alter behavior it describes.

Paths under `docs/superpowers/` cited in these notes are the maintainer's date-prefixed design
specs and implementation plans. They are git-ignored, local-only working notes and are not in
the public repository; when a cited file is missing, these notes are authoritative.

| File | Covers |
|------|--------|
| [networking.md](networking.md) | Per-organization overlay networks, the panel domain (the UI behind Traefik), domains/TLS, route exposure and protection (basic-auth, IP allowlist), shared hosts by path, redirects to the primary domain, raw TCP/UDP ports, gateway timeouts, the firewall dead-man switch, overlay MTU |
| [deploy.md](deploy.md) | Deploy invariants (convergence, settle, Stop cancels an unapplied deploy, jobs carry their tag, typed refusals), lifecycle controls, advanced container settings, resource defaults and build caps, registries, credential host binding, build secrets and private git, GitHub auto-deploy, app volumes |
| [databases.md](databases.md) | DB instances and logical databases, engine drivers (Postgres, Redis, DragonFly, Valkey, MinIO/Silo), DB→app links, S3 buckets and bucket backups, database backups to S3, single-writer protection |
| [cluster.md](cluster.md) | Worker nodes and placement, node-aware exec, the topology map, systems and the environment canvas, cluster-wide monitoring |
| [operations.md](operations.md) | Self-update, Krill state backup, the observability agent, app metrics, notifications and the digest, the log viewer, the web terminal, logging, the release image and installer, shutdown and systemd pitfalls |
| [agent-api.md](agent-api.md) | The MCP + REST agent API: operations, token auth, MCP session binding, provisioning |
| [security.md](security.md) | Tenancy chain-checks, RBAC, instance operator vs organization admin, login hardening, password changes, secret encryption |
| [ui.md](ui.md) | i18n and lowercase UI text, form guards, CSS/Tailwind, the page frame, confirm dialogs and terminals, templ traps |
| [code-map.md](code-map.md) | Detailed package map, data model key facts, the migration compatibility policy and migration pitfalls |

User-facing documentation lives elsewhere: [install](../install.md),
[configuration](../configuration.md) (every `KRILL_*` variable), [architecture](../architecture.md)
and the [guides](../guides/). What is done and what still waits for live acceptance is in
[ROADMAP.md](../../ROADMAP.md).

## Feature status trail

The full status paragraph as it stood when these notes were split out of the agent
instructions (2026-11-25). ROADMAP.md is the maintained source.

Phases 0, 1, 2, 2.5, 3, **4, 5** are DONE (login, image apps, Swarm services, Traefik routing, live logs, rolling updates, Dockerfile build+deploy, deploy history, UI design system + i18n, managed Postgres/Redis with volumes and external ports, multi/custom domains per app + per-domain Let's Encrypt HTTPS, **Postgres backups to S3/MinIO with cron + retention + restore**). **Phase 7 (realtime/ops)** is DONE except email/Slack: Telegram notifications, web terminal, host monitoring, and the structured log viewer all shipped. Tech-debt backlog for Phases 1–3 is fully closed. The **deploy-parity** track (gaps vs Dokploy for deploying a real app) is now **fully closed**: registry credentials (private image pull), advanced container settings (resources/replicas/restart/healthcheck), app lifecycle controls (stop/start via Deploy/Reload/Rebuild/Stop), gateway route exposure (per-domain public-path allow-list, internal-by-default), container command override (CMD args via the Advanced tab, e.g. `start-dev` for Keycloak), UI delete buttons for apps/environments/projects, **app volumes/mounts + volume backup/restore, DB→app connection-string injection, raw TCP/UDP published ports, build secrets/build-args + private-git clone, and per-domain route protection (basic-auth + IP-allowlist, the "who" axis) are all DONE**. [Multi-server (cluster)](cluster.md#multi-server-cluster) Stage 1+2 (SSH node join, placement, DB-on-node) is merged to master and live-checked on 2 nodes. **Phase 6 (GitHub auto-deploy)** is DONE: per-app, opt-in, webhook + PAT — a GitHub push webhook for Dockerfile/git apps and a CI deploy-hook for image apps. **Cluster-wide monitoring** is DONE: the sampler SSH-tunnels each worker's docker socket for per-node CPU/mem (control-plane + workers), shown on the Monitoring page with a node selector (migration 000027). **DB instances (2026-07)** is DONE: managed Postgres/Redis was rebuilt from one-container-per-database into org-level DB instances holding env-scoped logical databases (migrations 000029/000030) — see [DB instances](databases.md#db-instances). [Topology (visual cluster map)](cluster.md#topology-visual-cluster-map) is DONE (v1 2026-07-04 + v2 2026-07-05): an org-scoped, admin-gated page draws the cluster as node lanes holding apps/DB instances with colored app↔DB threads; v2 adds an ingress lane, directional arrows, `env_text`-DSN link detection, and link collapsing — no migration, see [Topology](cluster.md#topology-visual-cluster-map). **Backup UX simplification** (2026-07-05) is DONE: schedule presets (including on-demand) plus friendlier labels and inline storage setup replace the raw-cron form; the S3/cron engine itself is unchanged. **Stateful services via engine drivers (2026-07-08)** is DONE: managed DBs were refactored behind a per-engine `Driver` abstraction (`internal/dbservice/drivers`), adding **DragonFly** (Redis-compatible) and **MinIO** (S3-compatible, dual API+console external ports, engine-aware S3 app-linking) alongside Postgres/Redis — migrations 000035/000036/000037; OpenSearch + sub-resources (buckets/indices) deferred — see [Stateful services](databases.md#stateful-services--engine-drivers). **Phase 8 (flexible state placement)** is DONE (2026-07-11; live-accepted 2026-07-22 on a throwaway Colima VM — external + local + upgrade + fail-closed negative all green; the full install from a GitHub release on a fresh VM has not been run yet, though the download itself was verified with v0.1.0 — see [ROADMAP.md](../../ROADMAP.md)): the installer can point a fresh install at an external managed Postgres via `KRILL_DATABASE_URL` (skips the local `krill-postgres` container, fail-closed connectivity preflight BEFORE writing `krill.env`, `mask_dsn` so the DSN password never leaks) — **installer-only**, since the Go control-plane is already DSN-driven (no migrations); Redis from the original wording was moot (control-plane state is Postgres-only, no client/dep). See `docs/superpowers/specs/2026-07-11-krill-phase8-flexible-state-placement-design.md` / `docs/superpowers/plans/2026-07-11-krill-phase8-flexible-state-placement.md`. **Agent API (MCP + REST, 2026-08-13)** is DONE in code (branch `feat/mcp-agent-api`; live acceptance pending — no MCP client has connected yet): twelve read/write operations over existing apps, exposed twice (`/api/v1` + `/mcp`) behind org-scoped bearer tokens (migration 000040) — see [Agent API](agent-api.md#agent-api--mcp--rest). **Security hardening (2026-09-12)** is DONE in code: Git/registry credentials are bound to their own host, users can change their own password (forced for anyone added to an org for the first time), apps and DB instances get default CPU/memory limits, deploys are capped per organization on top of the existing per-app cap with a periodic BuildKit cache prune, the installer moves the control-plane Postgres onto its own Docker network, and every organization now gets its own overlay network with a background migrator that moves existing services onto it — see [Per-organization networks](networking.md#per-organization-networks), [Credential host binding](deploy.md#credential-host-binding), [Password changes](security.md#password-changes), and [Resource defaults & build caps](deploy.md#resource-defaults--build-caps). Live acceptance of the network migration on a real Swarm cluster and of the installer's Postgres move on a real VPS are both open — see [ROADMAP.md](../../ROADMAP.md). **Panel domain (2026-09-13)** is DONE in code (branch `feat/panel-behind-traefik`; live acceptance pending on a real VPS): the Krill UI itself gets a domain + Let's Encrypt HTTPS from **Settings → Panel domain**, with an anti-lockout confirmation and an optional firewall close of the UI port (migration 000045) — see [Panel domain](networking.md#panel-domain). **Self-update from the UI (2026-09-15)** is DONE (branch `feat/self-update`; live-accepted 2026-09-15 on a disposable Lima VM with throwaway releases via `make acceptance-selfupdate` — a real VPS and the panel-domain path are still open, see ROADMAP): an instance admin installs a newer Krill release from **Settings → Updates**, with a dead-man rollback to the previous binary if the new one never comes up — see [Self-update](operations.md#self-update). **Observability agent (2026-09)** is DONE in code (branch `feat/observability-agent`; live acceptance on a real two-node cluster pending, see ROADMAP): an opt-in Grafana Alloy agent, one global Swarm service task per node, ships host metrics and every container's logs to a Prometheus-compatible receiver and Loki that you provide — Krill keeps none of it — configured from **Settings → Observability** (migration 000047) — see [Observability agent](operations.md#observability-agent). **Krill state backup (2026-11-20)** is DONE (branch `feat/state-backup`; accepted 2026-11-21 on a disposable Lima VM by `make acceptance-statebackup` — runbook A on one VM after a full wipe, runbook B, the restore test; an external database with `verify-full` and the pre-update snapshot on a real VPS are still open, see ROADMAP): the control-plane Postgres is dumped on a schedule and before every UI update, age-encrypted and uploaded to S3 from **Settings → Krill backups** (migration 000062) — see [Krill state backup](operations.md#krill-state-backup). **Still open:** email/Slack notifications and live acceptance of the MinIO/DragonFly track (Phase 8 live acceptance passed 2026-07-22) — see [ROADMAP.md](../../ROADMAP.md). The bot's HTTPS webhook + DB durability + private-image pull are all unblocked.
